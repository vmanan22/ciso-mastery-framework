# Technical Decision Making

> Make and document sound technical decisions with clear trade-off analysis.

---

## Learning Objectives

- [ ] Write clear Architecture Decision Records (ADRs)
- [ ] Evaluate technical trade-offs systematically (not by gut feel)
- [ ] Consider security, cost, performance, and maintainability in every decision
- [ ] Use decision matrices and weighted scoring when appropriate
- [ ] Communicate technical decisions to non-technical stakeholders
- [ ] Know when to build vs. buy vs. open-source
- [ ] Make reversible decisions quickly and irreversible ones carefully

---

## ADR Template

```markdown
# ADR-NNN: [Decision Title]

## Status
[Proposed | Accepted | Deprecated | Superseded]

## Context
What is the problem? Why does a decision need to be made?

## Options Considered
1. **Option A** — Description, pros, cons
2. **Option B** — Description, pros, cons
3. **Option C** — Description, pros, cons

## Decision
What was decided and why?

## Consequences
- What are the positive consequences?
- What are the negative consequences?
- What are the security implications?
- What becomes easier or harder?

## Security Implications
- What new attack surface does this introduce?
- What controls are needed?
```

## Exercise Types

| Type | Description |
|------|-------------|
| ADR Writing | Write an ADR for a real technical decision |
| Trade-off Analysis | Compare 3 solutions across 5+ dimensions |
| Build vs. Buy | Evaluate whether to build internally or purchase a tool |
| Tech Stack Selection | Choose a tech stack for a specific use case with rationale |
| Post-Mortem Decision Review | Analyze a past technical decision and evaluate what you'd change |
