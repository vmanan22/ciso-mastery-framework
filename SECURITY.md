# Security Policy

> CLOS is dedicated to building trustworthy, evidence-backed security architectures. We appreciate the responsible disclosure of any security vulnerabilities found within our code or reference architectures.

---

## 🛡️ Supported Versions

We actively maintain and provide security updates for the current major milestone:

| Version | Supported |
| :---: | :---: |
| **v0.1.x** | ✅ Active Support |
| **< v0.1** | ❌ End of Life |

---

## 🔒 Reporting a Vulnerability

If you discover a security vulnerability in CLOS:

1. **Do NOT open a public GitHub issue.**
2. Report the vulnerability privately via **[GitHub Private Vulnerability Reporting](https://github.com/vmanan22/ciso-mastery-framework/security/advisories/new)**.
3. Include detailed reproduction steps, proof of concept (PoC), and potential impact.

---

## ⏱️ Response & Disclosure Timelines

* **Initial Acknowledgment**: Within 48 hours of receipt.
* **Triage & Assessment**: Within 5 business days.
* **Remediation & Release**: Target resolution within 30 days depending on severity.
* **Public Disclosure**: Coordinated disclosure after a fix has been tested and released.

---

## 🚫 Out of Scope

* Volumetric / Denial-of-Service (DoS) attacks against demo endpoints.
* Issues regarding third-party SaaS platforms without a reproducible flaw in CLOS reference code.
